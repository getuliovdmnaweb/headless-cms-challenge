Who uses it

Two types of users

🧑‍💼
Content admin

Defines what content looks like and creates the actual content — no code required.

  • Create content type schemas (e.g. "Blog Post", "Product")
  • Define typed fields per schema (text, number, date, boolean, reference)
  • Create, edit, and delete content entries
  • Evolve schemas safely when requirements change
  • See all tabs reflect changes in real-time
👩‍💻
Developer / front-end consumer

Fetches published content via a read-only API to render in any front-end (web, mobile, app).

  • Query any content type by its slug
  • Get a flat JSON array of all entries
  • Fetch a single entry by ID
  • No authentication needed — public read endpoint
  • Works with any stack: React, Vue, Swift, Flutter…
⚡
Real-time collaboration

Multiple admins can work at the same time. Every change broadcasts instantly via Socket.IO to all open browser tabs — no page refresh needed.

  • New entries appear on all tabs automatically
  • Deleted entries disappear everywhere instantly
  • If a content type is deleted, dependent tabs redirect

Setup

How to run

1
Start the PostgreSQL database with Docker Compose
2
Start the backend API on port 4000
3
Start the frontend on port 5173
4
Open localhost:5173 in the browser
Prerequisites: Node.js ≥ 18 · Docker Desktop · npm
# 1. Start the database
docker compose up -d
 
# 2. Start the backend (port 4000)
cd backend && npm install && npm run dev
 
# 3. Start the frontend (port 5173)
cd frontend && npm install && npm run dev
 
# 4. Open the admin
open http://localhost:5173
# Run unit tests
cd backend && npm test
cd frontend && npm test
 
# Run E2E tests (stack must be running)
cd frontend && npm run test:e2e
